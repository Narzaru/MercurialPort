# Mercurial Port

![Build](https://github.com/Narzaru/MercurialPort/workflows/Build/badge.svg)

Плагин JetBrains IDE для ревью изменений Mercurial внутри IDE: список файлов ветки, дифф по каждому
файлу и отметки «просмотрено». Добавляет два
тул-окна — **Hg Changes** и **Hg File History** — и действия **Hg Export** в меню Tools.

## Возможности

**Hg Changes** — изменения ветки деревом по каталогам: у файла статус и `+N −M`, у каталога — сумма
по вложенным и сколько в нём просмотрено.

- Пять режимов сравнения:
  - `Uncommitted` — незакоммиченное в рабочей копии;
  - `Merge` — что написала ветка, против последней влитой в неё ревизии родительской ветки (её имя —
    в поле справа). Сделанное родительской веткой до этого момента стоит по обе стороны и в дифф не
    попадает, поэтому ветка с регулярными мержами ревьюится так же чисто, как без них;
  - `Base` — какой ветка стала, против ревизии, от которой её отвели. База не двигается, коммиты
    коллег в родительскую ветку на список не влияют, перечислены только файлы собственных ревизий
    ветки. Влитое мержами в эти файлы здесь считается работой ветки;
  - `Changesets` — что сделали выбранные ревизии. Каждый файл сравнивается по своей паре ревизий —
    от состояния прямо перед первой его правкой до того, что из него сделали эти ревизии, — поэтому
    влитое из других веток не попадает ни в список, ни в дифф. Правая сторона здесь ревизия, а не
    файл на диске: незакоммиченного не видно, `Undo Changes` выключен;
  - `VS branch` — рабочая копия против последней ревизии ветки из поля справа, целиком и без
    ограничения по файлам.
- Поле ветки (режимы `Merge` и `VS branch`) подсказывает ветки по мере набора: `default` и открытые
  ветки, ещё не влитые в него. Точное имя ветки применяется само через мгновение после набора,
  любая другая ревизия — по `Enter` или при уходе из поля.
- `Base` и `Changesets` не загружают ветку больше заданного в настройках числа ревизий (по умолчанию
  100) — так `default` или долгоживущая релизная ветка не кладут IDE.
- Полоса ревизий под списком (режимы ветки, тумблер `Revisions`): ревизии ветки галочками, слияния
  по умолчанию выключены. Снятая галочка убирает файлы ревизии из списка и двигает базу сравнения;
  выбор хранится по имени ветки, `Reset` возвращает умолчание.
- Отметки «просмотрено»: клик по колонке с точкой или `Space`, у каталога — сразу всё содержимое.
  Переход на файл тоже ставит отметку, поэтому ветка проходится одними стрелками. Отметка привязана
  к ветке и к диффу файла: изменился дифф — файл снова не просмотрен, вернули правку — отметка
  вернулась. Отметки хранятся в проекте для четырёх последних веток, до 1000 файлов на ветку, и
  переживают перезапуск IDE; прогресс виден как `12/59 reviewed`, пункт `Clear Reviewed` в меню ⋮
  сбрасывает отметки текущей ветки.
- Дифф по одинарному клику, открытие файла — по двойному; дифф всегда в одной вкладке, фокус
  остаётся в списке.
- **Откат выбранных файлов** (`hg revert`) прямо из списка, с подтверждением и перечнем того, что
  будет откачено: в режиме незакоммиченного возвращает файл к последнему коммиту, в режимах ветки —
  к базовой ревизии сравнения. Переименование откатывается вместе с исходным путём.
- Фильтры по подстроке пути, показ неотслеживаемых файлов и файлов без реальных изменений, режим
  TODO — TODO-комментарии из изменённых файлов, включая несохранённые правки.
- Переименование показано одной строкой со статусом `→`, а не парой «удалено + добавлено».

**Hg File History** — полная история файла: ревизия, узел, дата, автор, сообщение. Окно следует за
файлом в редакторе и за выбором в Hg Changes.

- Клик по ревизии показывает, что изменила именно она (сравнение с первым родителем).
- Несколько ревизий, выделенных `Ctrl`- или `Shift`-кликом, складываются в одно изменение: слева
  файл у первого родителя самой старой из выбранных, справа — на самой новой.
- Содержимое ревизии можно извлечь во временную копию и открыть.

**Hg Export** — скопировать открытые в редакторе файлы в папку с отметкой времени, сохраняя
структуру каталогов проекта.

## Настройки

`Settings → Tools → Mercurial Port`:

- **Кодировка вывода `hg`.** Вывод читается как UTF-8, а строка, которая корректным UTF-8 не
  является — так выглядит сообщение коммита, набранное в системной кодировке, — декодируется
  выбранной здесь (на русской Windows умолчание cp1251).
- **Статус в заголовке вкладки редактора** — `Foo.cs [M]`, буква та же, что в списке изменений.
- **Игнорировать смену переводов строки при подсчёте `± строк`** — `hg diff --ignore-space-at-eol`.
  Файл, сохранённый с LF вместо CRLF, иначе читается как переписанный целиком: это шум, а не
  правка, и ревью-сервер его тоже не считает.
- **Command server** — запросы на чтение уходят в держащиеся наготове процессы
  `hg serve --cmdserver`, а не запускают `hg` каждый раз заново; запуск `hg` и есть основная цена
  загрузки. Число процессов на репозиторий настраивается, ожидающие запросы обслуживаются по очереди.
- **Самая большая ветка для `Base` и `Changesets`** — в ревизиях, `0` снимает ограничение.

### Как собирается дифф `Changesets`

**`Changesets are built by`** выбирает, по чьим правилам собирается режим:

- `Branch patches (plugin)` — по умолчанию, описан ниже;
- `Upsource review (as Upsource shows it)` — список файлов, `+N −M`, отметки и дифф такие, какими
  их показывает ревью в Upsource. Файлы — тронутые собственными ревизиями ветки (без слияний); у
  каждого файла своя старая сторона — родитель первой ревизии, которая его тронула; изменение
  прячется, только если оно пришло слиянием, менявшим файл с обеих сторон. Строки сравниваются так
  же, как в Upsource: сначала без учёта пробелов, затем отличия в пробелах отмечаются отдельно. На
  реальных ревью изменённые строки совпадают с Upsource примерно в 96% файлов; расходятся в основном
  переименования, которые Upsource находит по содержимому, и выбор между равноценными строками.

Для `Branch patches` левая сторона — голова, из которой **выкачены патчи собственных ревизий
ветки**, поэтому влитое мержами остаётся по обе стороны и в дифф не попадает. Две настройки решают,
насколько широко показывать саму правку.

**`Show a touched fragment whole`** (по умолчанию включено). Тронутый веткой фрагмент раскрывается
целиком, вместе с чужими строками внутри него, — так делает ревью-сервер. Снимите галочку, и в
диффе останутся только строки самой ветки: уже некуда, но правка бывает видна вне окружения —
дописанная веткой ветка `else` без пришедшего мержем `if` читается плохо.

**`Fragments are counted by`** — кто решает, где заканчивается изменение и начинается нетронутый
код. Отличия между вариантами мелкие и касаются границ: сколько соседних строк утянет за собой
раскрытый фрагмент.

| Вариант | Кто считает | Чем отличается |
|---|---|---|
| `IDE, ignoring whitespace at line ends` | движок сравнения IDE, краевые пробелы не в счёт | **Умолчание.** Ближе всех к ревью-серверу: его дифф запрашивается с игнором пробелов, и границы фрагментов тогда совпадают |
| `IDE` | тот же движок, пробелы в счёт | Строка, у которой изменились только отступ или хвост, считается изменённой, и фрагмент вокруг раскрывается шире |
| `IDE, as the diff viewer is set` | тот же движок, политика из списка `Do not ignore / Trim whitespaces / …` над сравнением | Список над диффом начинает решать не только подсветку, но и содержимое левой стороны; при его смене она пересобирается |
| `hg diff hunks` | сам `hg` (`hg diff -U 0`) | Тот же движок, что считает `+N −M`. С IDE расходится на мелочах вроде того, какая из двух одинаковых скобок считается изменённой |

Правки самой ветки ищутся всегда **без** игнора, какой бы вариант ни был выбран: иначе правка,
состоящая из одного переформатирования, стала бы одинаковой с обеих сторон и исчезла бы из диффа —
переключателем во вьюере её уже не вернуть.

## Требования

- Клиент Mercurial, доступный как `hg` в `PATH`.
- IDE на платформе сборки 252 и новее.

## Установка

Скачать zip из [последнего релиза](https://github.com/Narzaru/MercurialPort/releases/latest) и
поставить через <kbd>Settings</kbd> → <kbd>Plugins</kbd> → <kbd>⚙️</kbd> →
<kbd>Install Plugin from Disk…</kbd>, затем перезапустить IDE. В JetBrains Marketplace плагин не
публикуется.
